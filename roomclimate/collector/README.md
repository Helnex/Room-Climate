# collector

Программа на Raspberry Pi. Владелец: Хабарова Анастасия.

Сборщик читает DHT22 через GPIO и делает `POST {SERVER_URL}/telemetry`. На плате нет API и нет базы.

Сборщик работает на плате сам по себе (служба systemd) и шлёт показания каждые `PERIOD_SEC`
секунд, поэтому данные собираются и при закрытом мобильном приложении: телефон только читает
с сервера то, что плата уже прислала.

## Подключение DHT22

| Вывод DHT22 | Raspberry Pi |
|---|---|
| VCC (+) | 3.3 V — физический пин 1 |
| DATA (out) | GPIO4 — физический пин 7 (`DHT_PIN=D4`) |
| GND (−) | GND — физический пин 6 |

Голому датчику (4 ножки) нужен подтягивающий резистор 4,7–10 кОм между DATA и 3.3 V; на модуле
с платой (3 ножки) он уже стоит. Питать от 3.3 V, а не от 5 V: GPIO Raspberry Pi не терпит 5 V.

DHT22 иногда не отвечает («checksum did not validate») — это нормально: сборщик повторяет чтение
до 5 раз через 2 секунды, неправдоподобные значения (вне −40…80 °C и 0…100 %) не отправляет, а
после серии сбоев открывает датчик заново.

## Если пропала связь

Сервер перезапускается или пропал Wi-Fi — показания не теряются: сборщик продолжает мерить
каждые `PERIOD_SEC` и складывает их в буфер (`/var/lib/roomclimate/buffer.jsonl`, переживает
перезагрузку). Когда связь вернулась, накопленное досылается порциями по 30 вместе со временем
замера — в истории и на графиках дыры не будет. Досланные показания не вызывают уведомлений
(тревога о том, что было час назад, уже бесполезна).

У Raspberry Pi нет часов на батарейке, и без интернета после включения её время неверное.
Поэтому для показаний из той же загрузки время замера пересчитывается по монотонным часам в
момент досылки, когда время уже точное. Буфер ограничен `BUFFER_MAX` (20 000 ≈ 2,5 суток при
периоде 10 с), сервер принимает показания не старше недели.

## Сигнал на плате: светодиод и пищалка

Когда температура, влажность или CO₂ выходят за пороги, на плате загорается светодиод, а
пищалка коротко пищит два раза (один раз на новую тревогу, не каждые 10 секунд). Пороги —
те же, что в приложении («Настройки»): сборщик берёт их с сервера раз в 5 минут, а без связи
работает с последними полученными. Для CO₂ порог 1000 ppm.

| Деталь | Подключение | Настройка |
|---|---|---|
| Светодиод | длинная ножка → GPIO27 (пин 13) через резистор 220–330 Ом, короткая → GND (пин 14) | `ALARM_LED_PIN=D27` |
| Активная пищалка 3.3 В | «+» → GPIO22 (пин 15), «−» → GND (пин 20) | `BUZZER_PIN=D22` |

Не задано ни одного вывода — сигнал выключен.

## Состояние платы в приложении

Раз в минуту (`STATUS_SEC`) сборщик сообщает серверу о самой плате: температура процессора,
сеть Wi-Fi и уровень сигнала, IP, время без перезагрузки, версия сборщика (коммит git),
сколько показаний ждёт в буфере, какие датчики подключены и горит ли сигнал. В приложении это
карточка «Raspberry Pi» на экране «Устройства»: если пульса нет дольше 3 минут — «Плата не на
связи». Процессор горячее 70 °C — приложение подскажет поставить радиатор.

## Поправка датчика

DHT22 может ошибаться на ±0,5 °C и ±2–5 % — у каждого экземпляра по-своему. Положите плату
рядом с точным градусником/гигрометром на 15–20 минут и сравните с журналом
(`journalctl -u roomclimate-collector -f`). Разницу запишите в `/etc/roomclimate/collector.env`:
показывает на 0,8 °C больше — `TEMP_OFFSET=-0.8`, на 4 % меньше влажности —
`HUMIDITY_OFFSET=4`. Затем `sudo systemctl restart roomclimate-collector`.

## Дополнительные датчики: CO₂, свет, движение

Включаются переменной `EXTRA_SENSORS` (через запятую, например `co2,light,motion`) и уходят
в том же запросе, что и температура.

**`EXTRA_SENSORS=auto`** (по умолчанию в `install-service.sh`) — сборщик сам ищет подключённые
MH-Z19 (UART) и BH1750 (I2C): при старте и потом раз в `DETECT_SEC` (60 с). Воткнули датчик на
работающей плате — через минуту в журнале «найден датчик…», и его показания уходят на сервер.
Выдернули — после `LOST_AFTER` (5) пустых чтений подряд он убирается из списка и снова ищется.
Датчик движения так не найти (у PIR «никого нет» и «не подключён» одинаковы) — его включают
явно: `EXTRA_SENSORS=auto,motion`. Найденные датчики видны в «Состоянии платы» в приложении.

**Сервер знает только показатели из своей базы** (справочник заводится миграцией, см.
README сервера). Если датчик шлёт показатель, которого там нет, сервер отвечает 422 — сборщик
пишет в журнал «сервер не знает показатель …, добавьте его миграцией», остальные показания
отправляет как обычно, а незнакомый пробует снова раз в `RECHECK_UNKNOWN_SEC` (10 мин) —
после миграции он пойдёт сам, без перезапуска платы. В приложении: «Добавить датчик» → показатель, затем
«Добавить метрику» — карточка появится на дашборде.

| Датчик | Что измеряет | Подключение к Raspberry Pi | Включить |
|---|---|---|---|
| MH-Z19B (`co2`) | CO₂, ppm | Vin → 5 V (пин 2), GND → пин 6, TX → RXD GPIO15 (пин 10), RX → TXD GPIO14 (пин 8) | `raspi-config` → Interface Options → Serial Port: консоль «нет», порт «да» |
| BH1750 (`light`) | Освещённость, лк | VCC → 3.3 V (пин 1), GND → пин 9, SDA → GPIO2 (пин 3), SCL → GPIO3 (пин 5) | `raspi-config` → Interface Options → I2C |
| HC-SR501 (`motion`) | Движение (1 / 0) | VCC → 5 V (пин 4), GND → пин 14, OUT → GPIO17 (пин 11, `MOTION_PIN=D17`) | ничего |

MH-Z19 после включения греется около 3 минут — до этого сборщик отбрасывает его показания.
Выход HC-SR501 — 3.3 V, его можно подключать к GPIO напрямую. Движение считается «есть»
ещё `MOTION_HOLD_SEC` (60 с) после срабатывания, чтобы короткий импульс не потерялся между
отправками. Без железа (`SENSOR=fake` или ПК) все доп. датчики шлют тестовые значения.

## Настройки (переменные окружения)

| Переменная | По умолчанию | Что это |
|---|---|---|
| `SERVER_URL` | `http://127.0.0.1:8000` | Адрес сервера: дома `http://192.168.1.12:8000`, из интернета `https://api.climate-room.online` |
| `DEVICE_ID` | `pi-1` | Имя платы (латиница, цифры, `_ . -`) |
| `PERIOD_SEC` | `10` | Период отправки, не меньше 2 с |
| `INGEST_TOKEN` | — | Тот же, что в `server/.env` |
| `SENSOR` | `auto` | `auto` — DHT22, а без библиотеки тестовые значения; `dht22` — только датчик; `fake` — тестовые значения |
| `DHT_PIN` | `D4` | Вывод DATA по нумерации BCM |
| `TEMP_OFFSET`, `HUMIDITY_OFFSET` | `0` | Поправка датчика (см. ниже) |
| `BUFFER_PATH`, `BUFFER_MAX` | `/var/lib/roomclimate/buffer.jsonl`, `20000` | Буфер показаний без связи |
| `ALARM_LED_PIN`, `BUZZER_PIN` | — | Выводы светодиода и пищалки сигнала (BCM) |
| `THRESHOLDS_SEC` | `300` | Как часто брать пороги с сервера |
| `STATUS_SEC` | `60` | Как часто отправлять состояние платы |
| `EXTRA_SENSORS` | — | Доп. датчики: `auto` (найти самому) или `co2`, `light`, `motion` через запятую |
| `DETECT_SEC`, `LOST_AFTER` | `60`, `5` | Режим `auto`: как часто искать новые датчики; через сколько пустых чтений считать датчик отключённым |
| `RECHECK_UNKNOWN_SEC` | `600` | Через сколько снова пробовать показатель, которого нет в базе сервера |
| `CO2_PORT` | `/dev/serial0` | UART датчика MH-Z19 |
| `LIGHT_BUS`, `LIGHT_ADDR` | `1`, `0x23` | Шина и адрес I2C датчика BH1750 |
| `MOTION_PIN` | `D17` | Вывод OUT датчика движения (BCM) |
| `MOTION_HOLD_SEC` | `60` | Сколько секунд держать «есть движение» после срабатывания |

## Генератор данных: платы без железа

`fake_boards.py` — несколько «плат» в одном процессе: правдоподобные показания (суточный ход
температуры, влажность, по желанию CO₂ / свет / движение) и «состояние платы». Платы `pi-2` и
`pi-3` заведены в базу сервера («Плата № 0002 / 0003») — для проверки помещений «Склад1 / Склад2»
без второй Raspberry Pi.

```bash
python fake_boards.py http://192.168.1.12:8000 pi-2:18 pi-3:24 --extra co2,light
python fake_boards.py http://192.168.1.12:8000 pi-2 --backfill 6 --once   # история за 6 часов для графиков
```

`INGEST_TOKEN` берётся из окружения или из `server/.env`.

## Проверка цепочки на плате: «воткнул датчик → увидел в приложении»

1. На Pi: `sudo ./update.sh`, в `/etc/roomclimate/collector.env` — `DEVICE_ID=pi-1`
   («Плата № 0001»), `SERVER_URL`, `INGEST_TOKEN`, `EXTRA_SENSORS=auto`.
   `journalctl -u roomclimate-collector -f` — показания уходят без ошибок.
2. В приложении: «Устройства» → «Добавить помещение» → Плата № 0001 → «Добавить датчик» →
   «Температура и влажность». Через 10–20 с в «Устройствах» видны температура и влажность.
3. Воткнуть BH1750 (или MH-Z19) на работающей плате. Через минуту в журнале: «найден датчик…».
4. Если такого датчика ещё нет в базе сервера — добавить миграцией (README сервера, раздел
   «Платы и датчики») и перезапустить сервер. В приложении: «Добавить датчик» → он в списке
   «Выбор датчика» → выбрать помещение → его показания в «Устройствах».
5. Повторить с нуля: в приложении датчик → «Отвязать от платы» (или удалить запись и завести
   новой миграцией).
6. Вторая плата: `python fake_boards.py <сервер> pi-2` → помещение «Склад2» с Платой № 0002 —
   у Склада1 и Склада2 разные показания.

## Проверка с ПК без платы

С ПК, где уже запущен Docker-сервер (библиотеки не нужны — уйдут тестовые значения):

```powershell
cd collector
python collector.py
```

На другой сервер и с токеном:

```powershell
$env:SERVER_URL="http://192.168.1.12:8000"
$env:INGEST_TOKEN="тот-же-секрет-что-на-сервере"
python collector.py
```

Тесты (датчик и сервер подменены заглушками):

```powershell
python test_collector.py
python test_extra_sensors.py
python test_buffer.py
python test_alarm.py
python test_board_status.py
```

## Автозапуск на Raspberry Pi (служба systemd)

Чтобы сборщик запускался сам при включении платы и перезапускался после сбоев:

```bash
cd roomclimate/collector
chmod +x install-service.sh
sudo ./install-service.sh
```

Скрипт поставит библиотеку DHT22 в `.venv` рядом со сборщиком (в Raspberry Pi OS системный
`pip` запрещён) и спросит адрес сервера (например `http://192.168.1.12:8000`), имя платы (`pi-1`),
вывод датчика (`D4`) и `INGEST_TOKEN` — его взять из `roomclimate/server/.env` на компьютере
(создаётся `scripts/start.ps1`). Настройки сохраняются в `/etc/roomclimate/collector.env`
(права 640, токен не попадает в репозиторий).

| Команда | Что делает |
|---|---|
| `systemctl status roomclimate-collector` | Работает ли служба |
| `journalctl -u roomclimate-collector -f` | Журнал отправки показаний в реальном времени |
| `sudo systemctl restart roomclimate-collector` | Перезапуск (например, после правки `collector.env`) |
| `./update.sh --check` | Есть ли новая версия на GitHub |
| `sudo ./update.sh` | Обновить: скачать код, доставить библиотеки, перезапустить службу |
| `sudo ./install-service.sh --uninstall` | Удалить службу |

Служба ждёт сеть (`network-online.target`) и перезапускается через 5 с после любого падения;
внутри сборщик и так переживает пропадание сервера (повтор с паузой до 60 с).
