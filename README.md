# RoomClimate - система мониторинга климата в помещении
Мобильное приложение для мониторинга температуры и влажности в помещении в реальном времени с получением уведомлений при выходе показателей за допустимые границы. Приложение предусмотрено для сотрудников складов, цехов и производственных участков, где критичны температурно-влажностные условия, а также для владельцев квартир, домов и офисов, желающих контролировать климат в помещении.
# Задачи
   Подключение датчика температуры и влажности к Raspberry Pi, чтение данных через GPIO, отправка телеметрии на сервер.
   Разработка backend на Linux: REST API, хранение истории измерений.
   Android-приложение: дашборд с текущими показателями, графики за сутки.
# Функциональные требования
  - Система должна считывать температуру и влажность с датчика
  - Система должна сохранять каждое измерение в базу данных
  - Система должна предоставлять текущие показатели по запросу от мобильного приложения
  - Система должна предоставлять историю измерений за выбранный период.
  - Система должна принимать новые пороговые значения от мобильного приложения.
  - Приложение должно отображать текущую температуру и влажность в помещении.
  - Приложение должно строить график температуры и влажности за указанный период.
  - Приложение должно отправлять уведомление при температуре выше или ниже установленного критического значения.
# Нефункциональные требования
  - Система должна обеспечивать время отклика API не более 3 секунд.
  - Система должна работать на Raspberry Pi OS (64-bit) с Python 3.11+.
  - Система должна непрерывно работать.
  - Система должна работать в локальной сети Wi-Fi без доступа в интернет.
  - Приложение должно работать на Android 8.0 и выше.
  - Приложение должно быть разработано на языке Java с использованием актуальной версии Android SDK и Android Studio.
  - Приложение должно иметь интерфейс на русском языке.

# Принцип работы системы RoomClimate

Система состоит из трёх программ. На Raspberry Pi выполняются две: программа сбора данных collector.py и HTTP-сервер на FastAPI. На смартфоне выполняется Android-приложение.

Программа collector.py с заданным периодом (10 с) считывает показания датчика DHT22 с контакта GPIO4 и записывает температуру, влажность и метку времени в базу данных SQLite. Сбор выполняется независимо от Android-приложения: при закрытом клиенте измерения продолжают сохраняться.

FastAPI прослушивает порт 8000 и ожидает HTTP-запросы в локальной сети Wi‑Fi. К датчику и GPIO сервер не обращается: источником данных для ответов является SQLite.

Android-приложение с периодом 5 с отправляет запрос GET /telemetry/current на адрес Raspberry Pi в локальной сети (например, http://192.168.1.50:8000/api/v1/telemetry/current). FastAPI выбирает функцию, связанную с данным URL. Функция читает из базы последнее измерение, формирует ответ в формате JSON и возвращает его приложению по HTTP. Приложение отображает полученные значения на дашборде. Запрос GET /telemetry/history используется для построения графика за 24 часа, GET/PUT /settings — для чтения и сохранения порогов. Запрос GET /health проверяет доступность сервера и актуальность последнего измерения.

Если Raspberry Pi выключена или недоступна по сети, функция на сервере не вызывается; приложение получает ошибку связи. Уведомление о выходе температуры за порог формируется на стороне Android по данным JSON (state либо GET /alerts/active)














1. Пользователи и проблема
Пользователь 1. Сотрудник склада, цеха или участка. Нужно держать температуру и влажность в границах. Сейчас отклонение видно поздно: нет постоянного контроля и сигнала при нарушении порога.

Пользователь 2. Владелец квартиры, дома или офиса. Нужны текущие значения на телефоне, график за сутки и уведомление, если стало слишком жарко или холодно.

Проблема. Нет системы, которая непрерывно снимает температуру и влажность, хранит историю, показывает данные на Android и предупреждает при выходе за порог. Работа — в локальной Wi‑Fi, без интернета.

Продукт. RoomClimate: DHT22 на Raspberry Pi; на Pi две программы (сборщик пишет в SQLite, FastAPI отдаёт HTTP); Android показывает дашборд, график и уведомления.

2. User stories
US-1. Как сотрудник склада, я хочу видеть на телефоне текущие температуру и влажность, чтобы понять, в норме ли условия.

US-2. Как пользователь, я хочу график температуры и влажности за последние 24 часа, чтобы видеть динамику, а не одно число.

US-3. Как ответственный за помещение, я хочу задать нижний и верхний порог температуры, чтобы норма считалась по моим границам.

US-4. Как пользователь, я хочу уведомление, когда температура вышла за порог, чтобы среагировать, не глядя постоянно на экран.

3. Критерии приёмки
История закрыта, только если выполнены все пункты.

US-1

На главном экране Android — температура (°C) и влажность (%), интерфейс на русском.
Значения совпадают с GET /telemetry/current.
Если Pi недоступна — ошибка связи, приложение не падает.
Измерения идут на Pi сами (collector.py, DHT22, GPIO, запись в SQLite не реже чем раз в 10 с), даже когда телефон закрыт. FastAPI GPIO не читает.
US-2

По GET /telemetry/history строится график T и RH за сутки.
Нет данных — пустой экран, не краш.
Ответ API не дольше 3 с.
US-3

В приложении задаются temp_min и temp_max.
PUT /settings, затем GET /settings возвращает те же значения.
Если нижний порог ≥ верхнего — сервер отклоняет запрос.
US-4

T выше temp_max или ниже temp_min — уведомление на русском, указаны событие и значение.
Пока температура снова не в диапазоне, уведомление не повторяется на каждом опросе.
